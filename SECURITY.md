# Security Policy

## Supported versions

Security fixes are applied to the active `main` development line. Older
snapshots may not receive fixes.

## Reporting a vulnerability

Do not open a public issue for a vulnerability. Use GitHub's private
vulnerability reporting channel when enabled on the repository; otherwise,
contact the maintainer through the account that owns the repository. Include:

- a short description and impact;
- affected commit, package, or deployment mode;
- reproduction steps or a minimal proof of concept;
- any suggested mitigation.

Remove API keys, private novels, personal data, and generated private assets
from the report. The maintainer will acknowledge the report, investigate it,
and coordinate a disclosure timeline.

## Sensitive data rules

Never commit provider keys, database credentials, backup archives, local logs,
or user-authored fiction. Treat model responses and imported reference works
as potentially sensitive project data.
