# Chapter Edit Impact Preview

The chapter editor can assess one proposed rewrite before the author adopts it.
This helps a beginner understand a local change without tracing every related
fact or chapter manually. It extends the existing editor and AI impact owners;
it is not another writing or simulation runtime.

## Authority and scope

The registered structured prompt judges changed facts, supported conflicts and
possible effects. The host validates references, quotes and source identities.
Only the supplied current chapter, nearby planned chapters and bounded relevant
state are evidence. A prediction remains uncertain, and missing evidence cannot
establish that a candidate has no consequences.

The report is advisory. Preview writes no prose or canonical state, and a local
warning does not pause the global director. Adoption saves the actual proposed
prose through the existing conditional save; source-aware synchronization derives
facts from that committed text. A model forecast is never committed as state.

## Freshness and adoption

An assessment belongs to the exact saved source, local draft, candidate, selection
and relevant dependency revisions, plus its effective prepared prompt and model
configuration. Exact edit identities preserve raw bytes; artifact checkpoint
whitespace normalization is not a substitute for that identity.

The assessed adoption path rechecks its inputs and locks relevant database
dependencies inside the same prose-save transaction. The ordinary content
precondition remains mandatory. Changing the draft, candidate, selected range or
dependency requires a new assessment. Failure preserves the local draft and
candidate, including when another client has saved a different source.

Advisory receipts have a bounded lifetime on one service process. Expiration,
eviction, restart or a different worker requires reassessment and returns an
explicit conflict. Receipts are not durable edit approvals. Ordinary unassessed
editing remains available; report generation does not become a mandatory step
for novel completion.

## Ownership

- Chapter editor owns assessment, receipt policy, API and candidate interaction.
- Prompt Registry owns semantic instructions, output schema and prepared identity.
- Core CRUD owns conditional prose persistence and transactional preconditions.
- Chapter artifacts own source-aware post-save synchronization.

See [chapter production](./chapter-production-chain.md) for saved-prose and local
quality-debt rules, and the chapter editor's module boundary for exact limits and
extension points. UI acceptance and literary accuracy need author-reviewed
examples in addition to contract verification.
