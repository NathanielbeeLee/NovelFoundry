# Usage Guide

Choose the path that matches your goal. You do not need to read every document
before creating a novel.

## First run

Follow the [First novel walkthrough](#/docs/first-novel-walkthrough) from model
setup through the first chapter. The lighter [Getting Started](#/docs/module-onboarding)
guide explains the same path by product entry point.

## Understand the production chain

After completing a test novel, read:

- [End-to-end production](#/docs/end-to-end-production) for inputs, artifacts,
  and persistence;
- [AI director pipeline](#/docs/auto-director-pipeline) for stages, modes,
  checkpoints, and approvals;
- [Chapter execution](#/docs/chapter-execution) for generation, review, repair,
  quality debt, and state feedback;
- [Knowledge and retrieval](#/docs/knowledge-and-rag) for the assets that are
  recalled during planning and writing.

## Recover a task

Do not create a second project when a task pauses. Start with [Recovery by
phase](#/docs/recovery-by-phase), then use the [FAQ](#/docs/faq) and
[Troubleshooting](#/docs/troubleshooting) pages for model, task, retrieval, and
backup checks.

## Use derivative workspaces

Comic and short-drama workspaces extend completed novel content. They should be
opened after the main novel path has produced usable chapters, characters, and
scenes.

## Keep the paths separate

The first run is an operational path. Deep production documents explain the
system after you have seen it work. Recovery pages are for a concrete pause or
failure, not a required part of everyday writing.
