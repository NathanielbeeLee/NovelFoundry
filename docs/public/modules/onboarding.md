# Getting Started

Getting Started helps a first-time user make the AI environment usable and move
from one idea to a first readable chapter. It reads real provider, director,
novel, and chapter state, so progress does not need to be checked manually.

## Quick setup

When no usable text model is configured, the web and desktop clients open a
short setup flow:

1. Choose a provider or an OpenAI-compatible custom endpoint.
2. Enter the API key, API URL, and text model.
3. Test normal text and structured output.

The selected model can then support planning, writing, review, repair,
replanning, and summaries. Image models, retrieval, style assets, concurrency,
and detailed routing are optional enhancements.

Failed checks preserve the current input and identify whether normal text or
structured output needs attention.

## First novel milestones

1. **Environment**: one text model and core routes work.
2. **Idea and direction**: enter a premise and choose one of the generated book
   directions.
3. **Book preparation**: prepare the story, world, core cast, volume strategy,
   pacing, and chapter resources.
4. **Production mode**: choose guided creation or the professional workspace.
5. **First chapter**: generate, review, repair when needed, and open the saved
   chapter.

The page highlights one recommended action and explains why it is next. A pause
or failure changes the recommendation to diagnosis or recovery instead of
asking the user to create another novel.

## Guided creation and professional workspace

- **Guided creation** keeps producing the book while a read-only chapter shelf
  shows progress and stable drafts.
- **Professional workspace** exposes planning, characters, and chapter content
  for inspection and editing.

The first readable chapter completes the first-novel milestone in either mode.

## Optional enhancements

- Knowledge base for research and durable setting material.
- Style engine after you have useful writing samples.
- Image models for covers, character art, and illustrations.
- Detailed model routing when different tasks need different providers.

These improve long-term consistency but do not block the first chapter.
